# رابط اصلی وب زیباشی — پایهٔ مستقل Next.js

این پوشه آغاز رابط اصلی طبق ADR-03 دفترچه است: Next.js 16.4.6، React 19.3.1، TypeScript 7.0.2، App Router و strict types. نسخه‌ها و وابستگی‌های انتقالی در `package-lock.json` قفل شده‌اند. Node 22.18 یا جدیدتر در شاخهٔ 22، یا Node 24 لازم است. ساخت محلی این نوبت با Node 24.19 انجام شده؛ CI روی Node 22 تنظیم شده است.

تم تأییدشدهٔ تلگرامی از `web/preview` به کامپوننت‌های React منتقل شده: فهرست گفتگو، کاتالوگ، موجودی، حساب مشتری، فیلتر فاکتور، جزئیات، مراحل بسته و گفتگو. متن‌ها با React render می‌شوند؛ `innerHTML` و اسکریپت قدیمی در رابط جدید اجرا نمی‌شوند. snapshot حساب دقیقاً با نمونهٔ تأییدشده برابر است. نمایش پول از دادهٔ نمونه است و محاسبهٔ مالی یا تغییر قیمت در مرورگر اجرا نمی‌شود.

## اجرا

از ریشهٔ مخزن:

```bash
cd web/app
npm ci --ignore-scripts --no-fund --no-audit
NEXT_TELEMETRY_DISABLED=1 npm run build
npm run typecheck
npm test
python3 -m unittest discover -s scripts -p 'test_*.py'
python3 scripts/serve.py --port 4181
```

مرورگر: `http://127.0.0.1:4181`. سرور فقط loopback و GET/HEAD است. پورت ۴۱۸۱ مستقل از API فعال است. `serve.py` خروجی `out/` را نمایش می‌دهد؛ پردازش Next در زمان نمایش و اتصال به دیتابیس وجود ندارد. فایل HTML را مستقیم با file:// باز نکنید چون منابع Next مسیر مطلق دارند.

آزمون مرورگر با Python Playwright و Chromium در مسیر `/usr/lib/chromium/chromium`:

```bash
python3 scripts/check_browser.py --output /tmp/zibashe-next-preview
python3 scripts/package_export.py --output /tmp/zibashe-next-preview
```

سرور موقت آزمون با پایان کار بسته می‌شود. ZIP شامل `out/`، سرور نمایش و manifest است؛ پس از استخراج، همان دستور `python3 scripts/serve.py` اجرا شود. node_modules، سورس ERP و فایل محیط بسته‌بندی نمی‌شوند. این بسته برای مرور نمونه است، نه نصب production. پیش‌نمایش HTML تک‌فایلی قدیمی همچنان از `web/preview/export_preview.py` قابل تولید است.

## مرز این مرحله

- فقط fixture ساختگی؛ تمام سفارش‌ها، پرداخت‌ها، ورود، پیامک، تلگرام و ذخیره‌سازی غیرفعال‌اند. staff صرفاً نمایش طرح است و مجوز واقعی ایجاد نمی‌کند.
- build وجود `.env*` جز `.env.example` و تنظیم‌های اتصال دیتابیس/`NEXT_PUBLIC_*`/`ZIBASHE_WEB_*` را رد می‌کند. این guard مرز احراز هویت نیست؛ پروژه در این مرحله هیچ مسیر اتصال ندارد.
- CSP شبکه و ارسال فرم را می‌بندد. اسکریپت‌های داخلی hydration خروجی Next با SHA-256 همان سند مجاز می‌شوند؛ `unsafe-inline` و `unsafe-eval` فعال نشده است. داده‌های حساس در cache قرار نمی‌گیرند؛ تمام پاسخ‌ها `no-store` هستند.
- فونت، تصویر و فایل JS/CSS خارجی، Analytics، service worker و API proxy وجود ندارد. همهٔ منابع برای نمایش از همان خروجی محلی خوانده می‌شوند.
- این نسخه PWA نصب‌شدنی، ورود واقعی یا فروش آفلاین نیست. قطع اینترنت خارجی در production با این نمونه اثبات نمی‌شود؛ به زیرساخت ایران، هویت و فایل‌های مستقل نیاز دارد.
- build/test مستقل در `web-preview.yml` اضافه شده؛ اجرای مرورگر فعلاً محلی است. آزمون‌ها و تنظیمات .NET و استقرار فعلی تغییر نکرده‌اند. `.dockerignore` فقط خروجی‌ها و وابستگی‌های وب را از context کانتینر ERP کنار می‌گذارد.

گام بعدی آماده‌سازی قرارداد فقط‌خواندنی و مرز هویت سمت سرور در staging است: مالکیت جاری پس از انتقال، پرداخت جزئی، فاکتور لغوشده، فایل خصوصی، هدایا و نقش‌ها باید با سرویس مشترک بررسی شوند. تا تکمیل دروازه‌های دفترچه، اتصال مشتری واقعی و نویسندگی وب فعال نمی‌شود.
