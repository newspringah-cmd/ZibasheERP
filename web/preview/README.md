# پیش‌نمایش مستقل رابط زیباشی

مرحلهٔ آماده‌سازی غیرتولیدی P1، به دستور مدیر برای ادامهٔ کارهای مستقل در زمان تعویق خرید زیرساخت. gateهای P0 و بازیابی واقعی هنوز تأیید نشده‌اند. این صفحه، پیاده‌سازی Next.js یا ERP متصل و ورود امن نیست؛ نمونهٔ سبک و قابل بررسیِ چیدمان است و نباید روی production نصب شود.

```bash
python3 -m unittest discover -s web/preview -p 'test_*.py'
python3 web/preview/server.py --port 4180
```

فقط روی loopback گوش می‌دهد. اتصال دیتابیس در محیط و حالت Production را رد می‌کند. همهٔ پرچم‌های اتصال و عملیات باید خاموش باشند. GET فقط فایل‌های نمایشی فهرست‌شده و health را می‌دهد؛ مسیر API، فایل دیگر و همهٔ روش‌های نوشتنی رد می‌شوند. CSP اتصال شبکهٔ frontend، ارسال فرم و بارگذاری منابع خارجی را مسدود می‌کند. سرور اجازه خواندن دایرکتوری یا اجرای API نمی‌دهد. فایل env خوانده نمی‌شود؛ اعتبارنامه‌ای وارد تنظیمات نمونه نکنید.

داده‌ها ثابت و ساختگی‌اند؛ جست‌وجو و جابه‌جایی اتاق و جزئیات صرفاً رفتار نمایشی هستند. مبلغ، بدهی، شمارنده، صف و تصویر بطری به رکورد واقعی وصل نیستند. دکمهٔ سفارش و ورودی پیام غیرفعال‌اند. نمای کارکنان به‌صورت نمایشی در دسترس است و مجوز واقعی کارکنان را ادعا نمی‌کند. برای اتصال بعدی باید ورود و مالکیت و نقش سمت سرور و عملیات مشترک و feature flag سمت سرور پیاده و آزمون شوند.

فایل‌های CSS و منطق نمایشی می‌توانند مبنای انتقال به رابط اصلی Next.js باشند؛ محدودیت CSP و server.py برای همین نمونه‌اند و جای امنیت و پیکربندی production نیستند.

## اصلاح تم به الگوی تلگرام

تم روشن با فهرست چت‌ها، آواتار دایره‌ای، نوار آبی، پیام سنجاق‌شده، تصویر زمینهٔ SVG محلی، حباب ورودی سفید و خروجی سبز و timestamp و دکمهٔ زیر پیام ساخته شده است. در موبایل، بازگشت فهرست گفتگوها را باز می‌کند و انتخاب چت به گفتگو برمی‌گردد. تمام محتوای پیام‌ها و اعداد، نمونه است؛ وضعیت واقعی ارسال یا read receipt را اثبات نمی‌کند.

آزمون مرورگر بازتولیدپذیر با Playwright و Chromium روی سرور موقت loopback:

```bash
python3 web/preview/check_browser.py --output /tmp/zibashe-telegram-preview
```

این آزمون اکنون ۴۲ بررسی روی دسکتاپ و عرض‌های موبایل ۳۲۰،۳۹۰،۷۴۰ دارد و سرور موقت خودش را می‌بندد. endpoint تولید و اعتبارنامه دریافت نمی‌کند. پیش‌نمایش وابستگی خارجی ندارد؛ نسخهٔ HTML تحویلی CSS، SVG و JS را در خودش دارد.

## حساب مشتری، مرحلهٔ نمایشی

`account.js` یک snapshot ثابت و تغییرناپذیر ساختگی دارد: فیلتر فاکتورهای پرداخت‌شده و باز، جزئیات عطر و شیشه، پرداخت جزئی تأییدشده، بدهی باقی‌مانده، سابقهٔ بسته‌ها و timeline. فاکتور موجودی و مقدار نیم‌میل مشخص‌اند. تصویر نمونهٔ بسته شامل هدیهٔ دریافتی است و اقلام در انتظار ایران را شامل نمی‌شود؛ این صرفاً نمونهٔ نمایشی است، نه اثبات اصلاح گزارش هدایا در هستهٔ فعال.

UI مبلغ‌ها را از snapshot نشان می‌دهد، جمع مالی یا قیمت مجدد حساب نمی‌کند. هم‌خوانی جمع‌ها در fixture با آزمون مستقل بررسی می‌شود. این snapshot قرارداد نهایی API نیست و session یا مالکیت را تضمین نمی‌کند. هیچ شماره کارت، آدرس، جایگاه فیزیکی یا CustomerId واقعی وارد مرورگر نشده است. دریافت فایل و ارسال رسید غیرفعال است.

```bash
node --test web/preview/test_account.cjs
python3 web/preview/check_browser.py --output /tmp/zibashe-account-preview
python3 web/preview/export_preview.py --output /tmp/zibashe-account-preview
```

خروجی HTML و ZIP فقط منابع نمایشی ثابت و اسکرین‌شات‌های نام‌برده را شامل می‌شوند؛ هیچ فایل تنظیمات یا پوشهٔ دیگری بسته‌بندی نمی‌شود. بازکردن HTML آفلاین برای مرور طرح ممکن است، ولی امکان ثبت سفارش آفلاین ایجاد نمی‌کند.

گام فنی بعدی: آماده‌سازی پروژهٔ رابط اصلی مطابق ADR-03، سپس قرارداد فقط‌خواندنی مشترک با احراز هویت سمت سرور، مالکیت جاری فاکتور پس از انتقال، حذف اسناد لغوشده از بدهی، پرداخت جزئی و تطبیق با هسته. P0 و ورود واقعی P2 همچنان بازند.
