# آزمایش API فاکتور با نشست مشتری

این برنامهٔ مستقل روی HTTPS و آدرس محلی `127.0.0.1` اجرا می‌شود و دو حساب و فاکتور ساختگی دارد. کد یک‌بارمصرف در خروجی ترمینال همان فرایند نمایش داده می‌شود. گواهی HTTPS آزمایش در زمان اجرا ساخته می‌شود.

```bash
dotnet build tools/web-continuity/AccountApiPreview --configuration Release --warnaserror
python3 tools/web-continuity/AccountApiPreview/check_http.py
```

آزمون نسخهٔ ساخته‌شده را روی پورت آزاد اجرا می‌کند و پس از پایان می‌بندد. بررسی گواهی خودامضا فقط در کلاینت همین آزمون محلی کنار گذاشته می‌شود.

برای اجرای دستی، `dotnet run --project tools/web-continuity/AccountApiPreview -- 4182` را اجرا کنید. آدرس در خط `PREVIEW_URL` چاپ می‌شود. درخواست‌های POST به سرآیند `Origin` برابر همان آدرس نیاز دارند.

| روش و مسیر | رفتار |
| --- | --- |
| `POST /api/v2/session/sms/start` | با بدنهٔ JSON شامل `mobile` درخواست کد آزمایشی می‌دهد. دو شمارهٔ ساختگی در `SyntheticAccounts.cs` تعریف شده‌اند. |
| `POST /api/v2/session/sms/verify` | با `challengeId` و `code` نشست ۱۵ دقیقه‌ای و کوکی Secure، HttpOnly و SameSite=Strict صادر می‌کند. |
| `GET /api/v2/me/invoices` | فاکتور و خلاصهٔ مالی حساب نشست را می‌خواند. `page` و `pageSize` اختیاری‌اند. |
| `POST /api/v2/session/logout` | نشست را در سرور باطل می‌کند و دستور حذف کوکی را به کلاینت می‌دهد. |

نشست و چالش در حافظهٔ همین فرایند نگهداری می‌شوند. این آزمایش مسیر پیامک شبیه‌سازی‌شده است. پیش‌نمایش Next.js از خروجی ثابت خود استفاده می‌کند. ارسال واقعی پیامک، ورود تلگرام، پیوند تأییدشدهٔ موبایل با مشتری، و اتصال فرم وب به این نشست هنوز در انتظار پیاده‌سازی‌اند.
