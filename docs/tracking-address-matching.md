# Postal receiver matching against preparation addresses

Complete recipient names can be extracted from labelled fields (نام, نام و نام خانوادگی, گیرنده, بنام, برسد به), inline named suffixes after street addresses, and slash/newline-separated fields. Contact numbers, usernames and street-only fragments remain excluded. Existing fuzzy thresholds, distinct-customer ambiguity checks, OCR confidence gates and parcel ownership validation remain in force. Surnames alone are never auto-approved.

After active ERP parcels, exact full-name matches may use recent installed address messages in the configured preparation group. Automatic rechecks use the original batch timestamp so addresses or new parcel requests created later cannot silently retarget an earlier postal file. The context, address owner, active customer-group link and current parcel readiness must agree. Already dispatched prepared scopes are excluded. Legacy address-only parcels need no fabricated invoice/order/item. A manual placeholder with no delivery identity or connected group remains under destination review.

Unsent tracking cards provide «انتخاب از آدرس‌های آماده‌سازی». Suggestions explicitly show similar one/two-word recipient names, Telegram usernames and original address links in review captions and the paginated review list. Raw-address text similarities are labelled separately. They are advisory only, sorted by shared words, name relevance and recency, with links to the original preparation addresses and pagination. An administrator must select a destination, inspect the postal row against that address, then approve a versioned confirmation. The choice is bound to the operator, conversation, source dispatch fingerprint and current address/parcel. Duplicate callbacks, expired or changed previews and any prior send attempt are blocked. Package collisions remain blocked.

Manual approval only sets the selected dispatch Ready and appends a durable audit receipt. It preserves original OCR name, tracking digits and card, and creates no send job, invoice or shipment item. Separate Send confirmation remains required. Rebuild preserves explicit manual selections. Batch rematching uses conditional updates so a concurrent selection or send cannot be overwritten.

Tests use isolated SQL and fake Telegram. Live batch re-evaluation must preserve low-confidence OCR rows, sent/attempted rows, tracking codes and financial/fulfillment state, and must never automatically send postal notifications.
