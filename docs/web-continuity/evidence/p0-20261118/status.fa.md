# وضعیت اجرای P0 — ۱۸ نوامبر ۲۰۲۶

وضعیت: **شروع‌شده؛ دروازهٔ P0 هنوز بسته نشده است.** ابزار و شواهد پایه ساخته شده‌اند. هیچ قابلیت نوشتنی وب منتشر، migration اجرا، حساب مشتری ادغام یا دیتابیس جابه‌جا نشده است.

## خروجی اجرایی

- ابزار `tools/web-continuity/collect_repository.py` برای ثبت declarations کنترلرها و Workerها و ۱۹۰ شناسهٔ قابلیت؛ فقط سورس tracked را می‌خواند.
- برنامهٔ `tools/web-continuity/Probe` برای جمع‌آوری aggregateهای محدود و SELECT-only؛ بدون startup یا migration برنامه.
- آزمون collector با مخزن مصنوعی، فایل secret و کنترلر untracked؛ اثبات عدم ورود secret و فایل untracked به خروجی و عدم ادعای ممیزی runtime.
- build موفق probe؛ اجرای واقعی در container موقت read-only با ارتباط داخلی SQL و حساب برنامهٔ موجود، بدون توکن ربات در probe.
- رجیستر اولیهٔ وابستگی‌ها در `dependency-register.csv`؛ تأمین‌کننده و مسئول و شواهد دسترسی برخی ردیف‌ها هنوز باید تعیین شوند.

## وضعیت واقعی مشاهده‌شده

| معیار | مقدار | تفسیر |
|---|---:|---|
| حساب‌های حذف‌نشده | ۱۷۳۸ | تعداد رکورد؛ نه ادعای ۱۷۳۸ مشتری فعال هم‌زمان |
| سفارش‌های حذف‌نشده | ۵۸۴۶ | شمارش رکورد، نه فروش قطعی |
| فاکتورهای حذف‌نشده | ۵۸۳۵ | شامل وضعیت‌های مختلف |
| مشتری با سفارش ایجادشده در ۳۰ روز اخیر | ۹۳۰ | شاخص بر اساس CreatedAt؛ معادل خریدار پرداخت‌شده یا concurrency نیست |
| فایل دادهٔ تخصیص‌یافته SQL | ۶۴۸ MiB | اندازهٔ تخصیص‌یافته؛ نه میزان دقیق استفادهٔ صفحات |
| فایل لاگ تخصیص‌یافته SQL | ۴۷۴۴ MiB | جدا از فایل داده؛ شامل سقف ۱۰ GiB دادهٔ Express نیست |
| Edition | Express | برنامهٔ ظرفیت و بازیابی باید با همین Edition آزمایش شود |
| موبایل استاندارد ایران در فیلد Mobile | صفر از ۱۷۳۸ | پس از نرمال‌سازی ارقام و پیش‌شماره؛ مالکیت هیچ شماره‌ای اثبات نشده است |
| لیست دارای مرجع عکس تلگرام | ۱۸۴۲ | این تعداد اثبات نبود فایل مستقل نیست؛ پوشش آرشیو مستقل بررسی نشده است |

خواندن‌ها در لحظه‌های نزدیک انجام شده‌اند؛ snapshot تراکنشی منجمد مالی نیستند. مقادیر تماس و نام و آدرس و شناسهٔ مشتری در گزارش خروجی نیامده‌اند.

## تصمیم‌های حاصل برای پیاده‌سازی

۱. ورود پیامکی وب روی فیلد فعلی Mobile فعال نمی‌شود. ابتدا مسیر اتصالِ حساب تلگرامِ احراز‌شده به موبایل تأییدشده ساخته و پایلوت می‌شود. شمارهٔ آدرس پستی ممکن است متعلق به گیرندهٔ هدیه یا شخص دیگر باشد و مجوز ورود نیست.
۲. CustomerId ثابت می‌ماند. هیچ موبایل حدسی یا بازنویسی گروهی اطلاعات هویت در production انجام نمی‌شود. حساب مبهم مسیر بررسی انسانی دارد.
۳. آرشیو رسانه به گزارش پوشش و نگاشت دقیق نیاز دارد؛ وجود Telegram FileId به‌تنهایی دسترسی هنگام قطعی را تضمین نمی‌کند.
۴. تغییر یا کوچک‌کردن فایل لاگ SQL در این مرحله انجام نمی‌شود. recovery model و زنجیرهٔ backup و فضای دیسک و هدف بازیابی باید ابتدا بررسی شوند.
۵. شروع سایت روی هستهٔ فعلی، تا انتقال و آزمون مستقل داخل ایران، پشتیبانی از قطع بین‌الملل محسوب نمی‌شود.
۶. دروازه‌های دفترچه پابرجا هستند؛ جمع‌آوری baseline مجوز عرضهٔ خرید وب یا انتقال سرور نیست.

| مقصد ایران، DNS/TLS، پیامک و مسیر اضطراری | رجیستر اولیه؛ انتخاب ارائه‌دهنده با بودجه و آزمایش داخلی باقی است |

قدم اجرایی بعدی در همین مرحله: تکمیل شواهد backup/restore و ظرفیت و نقش‌ها؛ سپس P1 محیط مستقل و P2 پایلوت فقط‌خواندنی و اتصال هویت، بدون جابه‌جایی writer و بدون تغییر مسیر خرید مشتری‌های فعلی.
