# زیرساخت پیامکی مشتری، بدون فعال‌سازی واقعی

مدیر ورود با پیامک را انتخاب کرد و اعلام کرد هنوز پنل ندارد؛ درخواست این مرحله آماده‌کردن زیرساخت است. یوزرنیم روش ورود این نسخه نیست و پنل، پیامک یا هزینه‌ای فعال نشده است.

فرم `/login/` با سبک تلگرام، فیلد موبایل فارسی/عربی/بین‌المللی، خطای شماره نامعتبر و توضیح اتصال حساب قبلی ساخته شد. دکمهٔ واقعی ارسال غیرفعال است و ورود موفق یا کد نمایشی جعلی نشان داده نمی‌شود. state فرم با reload پاک می‌شود و شماره در storage/شبکه قرار نمی‌گیرد.

در Application، قرارداد directory فقط برای موبایل تأییدشده و یکتای CustomerId و adapter ارسال مستقل از سرویس‌دهنده، چالش **حافظه‌ایِ staging** و سیاست خواندن حساب/فاکتور/بسته اضافه شد. کد تصادفی شش‌رقمی، HMAC، انقضای سه دقیقه، مصرف اتمیک، پنج تلاش، محدودیت mobile/client و اعتبارسنجی اتصال جاری پیاده شده‌اند. هیچ HTTP endpoint، DI یا adapter دیتابیس/ارائه‌دهنده به API فعلی اضافه نشده است. proof مشتری، session یا نقش کارکنان نیست.

شواهد محلی:

- Application: تمام ۱۶۵ آزمون موفق، شامل ۱۵ آزمون جدید چالش و دسترسی. build Release با warn-as-error: صفر خطا/هشدار.
- Next: build بهینه و TypeScript موفق؛ ۶ آزمون Node موفق.
- مرز HTTP ثابت: ۱ آزمون با چندین assertion موفق، شامل مسیر `/login/`، عدم API و نوشتن، CSP و no-store.
- ۵۶ بررسی مرورگر موفق روی دسکتاپ و موبایل ۳۲۰/۳۹۰/۷۴۰؛ اعتبارسنجی موبایل، رد username، پاک‌شدن state پس از reload، عدم ذخیره‌سازی و تماس ERP، و حفظ تم/فاکتورها/بسته‌های نمونه. فرم موبایل تصویری بازبینی شد.

عبور P0/P2، ورود production، امنیت کامل HTTP/session، برابری زمان پاسخ برای جلوگیری از افشای وجود حساب، MFA کارکنان و پیوند واقعی موبایل هنوز تأیید نشده‌اند. صرفاً قرارداد پاسخ عمومی در core وجود دارد. پیاده‌سازی حافظه‌ای تک‌پردازه است؛ پیش از rollout به store مشترک اتمیک، edge limiting، cookie/CSRF، ابطال نشست و audit و سناریوهای outage نیاز دارد.

راهنمای کارهای بعدی در [ورود پیامکی](../../sms-login.fa.md) است. production، سفارش‌ها، دیتابیس، پیام‌های تلگرام، بک‌آپ و تنظیمات مالی تغییر نکرده‌اند.
