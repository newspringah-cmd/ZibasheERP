# حساب مشتری در پیش‌نمایش مستقل

ادامهٔ کار مستقل با تأیید تم شبیه تلگرام: «حساب من» اکنون فیلتر همه/پرداخت‌شده/در انتظار پرداخت، جزئیات فاکتور، تفکیک عطر و شیشه، پرداخت جزئی، بدهی باقی‌مانده، فهرست بسته‌ها و مراحل ارسال دارد. نشان موجودی، حجم ۱.۵ میل و هدیهٔ دریافتی در بستهٔ نمونه مشخص‌اند. جزئیات فاکتور در dialog باز می‌شود و با Escape یا بستن، کاربر به همان فهرست برمی‌گردد.

`account.js` فقط snapshot ثابت و تغییرناپذیر مصنوعی را نمایش می‌دهد. UI قیمت جدید یا جمع مالی از روی DOM حساب نمی‌کند. مجموع فاکتورهای پرداخت‌شدهٔ نمونه ۳۸۰٬۰۰۰، پرداخت جزئی فاکتورهای باز ۵۰٬۰۰۰ و بدهی باقی‌ماندهٔ نمونه ۶۳۰٬۰۰۰ تومان است. هم‌خوانی مبلغ خط/فاکتور/خلاصه و عدم تغییر snapshot با فیلتر و جزئیات آزموده شده است.

شواهد: ۴۲ بررسی مرورگر روی دسکتاپ و عرض‌های ۳۲۰/۳۹۰/۷۴۰، ۴ آزمون Node برای fixture، ۴ آزمون HTTP و پرچم‌های غیرفعال، syntax جاوااسکریپت و یکپارچگی خروجی HTML/ZIP موفق‌اند. تصاویر موبایل حساب و جزئیات فاکتور بازبینی شدند. گردش CI مستقل بدون secret یا دیتابیس برای آزمون‌های Node/HTTP و تحویل ZIP اضافه شده؛ اجرای remote آن هنوز در این گزارش تأیید نشده و مرورگر فعلاً در محیط محلی اجرا شده است.

این کار backend مالی، ورود واقعی، کنترل مالکیت، API یا PWA کامل نیست. رفتار هدایای نمونه شاهد اصلاح یا برابری هستهٔ عملیاتی نیست. هیچ هویت، آدرس، قیمت یا فاکتور واقعی خوانده نشده؛ هیچ پیام یا رسیدی ارسال نشده؛ source سرور فعال، دیتابیس، هزینه و بک‌آپ تغییری نکرده‌اند. گذر از P0/P2 همچنان تأیید نشده است. `server.py` همچنان loopback-only و GET/HEAD-only با `connect-src 'none'` و allowlist ثابت است.

گام بعدی: آماده‌سازی رابط اصلی Next.js/TypeScript طبق ADR-03 در محیط مستقل؛ سپس پیاده‌سازی قرارداد فقط‌خواندنی مشترک و آزمون سمت سرور برای نشست معتبر، مالکیت جاری، انتقال، پرداخت جزئی و فاکتور لغوشده، پیش از اتصال دادهٔ واقعی.
