# پایهٔ رابط اصلی Next.js، مستقل از ERP فعال

رابط تأییدشدهٔ تلگرامی به پروژهٔ `web/app` با Next.js 16.4.6، React 19.3.1 و TypeScript 7.0.2 منتقل شد. بخش‌های کاتالوگ، موجودی، حساب مشتری، فیلتر فاکتور، جزئیات مبلغ و مراحل بسته و گفتگو کامپوننت React هستند؛ کد `innerHTML` پیش‌نمایش قدیمی به برنامهٔ جدید وارد نشده است. snapshot حساب با همان دادهٔ نمونهٔ تأییدشده برابر است و آزمون migration این برابری را بررسی می‌کند.

نسخه‌ها و dependency tree با lockfile ثبت شده‌اند. نصب بدون lifecycle script موفق بوده و build بهینهٔ static export و strict typecheck موفق‌اند. در زمان ساخت، `.env*` و تنظیم اتصال ERP و public API رد می‌شوند؛ این guard جایگزین احراز هویت نیست. هنگام نمایش Node/Next backend اجرا نمی‌شود؛ سرور static فقط روی 127.0.0.1، GET/HEAD و فایل‌های خروجی مجاز است. CSP برای hydration هر سند از hash اسکریپت‌های همان سند استفاده می‌کند؛ اتصال شبکه، فرم و unsafe-inline/eval بسته‌اند. همهٔ فایل‌ها محلی و no-store هستند.

شاهد اجرای محلی در ۱۸ نوامبر ۲۰۲۶:

- build نهایی و TypeScript موفق، Node 24.19.0؛ CI روی Node 22 تنظیم شده ولی اجرای remote هنوز در این گزارش تأیید نشده است.
- ۴ آزمون Node: مرز تنظیم محیط، جلوگیری از اتصال، تطبیق مبلغ‌ها و برابری snapshot قبلی.
- ۱ آزمون HTTP با چندین assertion: CSP/hash، HEAD، no-store، رد API و traversal و روش‌های نوشتنی.
- ۴۵ بررسی مرورگر روی build نهایی، desktop و موبایل ۳۲۰/۳۹۰/۷۴۰: فیلترها و جزئیات، ناوبری، بدون overflow، بدون خطای JS/React/CSP، کاتالوگ اولیه بدون JS، منابع همگی محلی و بدون درخواست API. آیکن محلی اضافه شد تا ۴۰۴ favicon نیز برطرف شود.
- گزارش `npm audit --omit=dev` هنگام اجرا صفر vulnerability شناخته‌شده برای وابستگی‌های runtime نشان داد؛ این نتیجه تضمین دائمی امنیت نیست.
- تصویر دسکتاپ و جزئیات فاکتور موبایل بازبینی شد. بستهٔ ZIP خروجی ثابت، سرور محلی و manifest دارد؛ node_modules و محیط و سورس مالی در آن نیستند.

گره‌های P0، ورود امن، نقش‌ها و اتصال واقعی P2 هنوز بازند. هیچ session واقعی، API proxy، پیامک، Telegram، پرداخت یا نوشتن ERP و service worker فعال نشده است. PWA نصب‌شدنی و تحمل قطعی اینترنت در production هنوز پیاده/اثبات نشده‌اند. هیچ deploy، migration، تغییر داده، پرداخت هزینه یا تنظیم بک‌آپی انجام نشده است. `.dockerignore` فقط از ورود فایل‌های build/dependency/environment وب به context کانتینر ERP جلوگیری می‌کند.

گام بعد: قرارداد فقط‌خواندنی و هویت در staging مستقل، سپس کنترل مالکیت جاری و انتقال فاکتور، پرداخت جزئی و لغو و هدایا و فایل خصوصی با سرویس مشترک و شواهد تطبیق هسته، قبل از اتصال مشتری واقعی.
