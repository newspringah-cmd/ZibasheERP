# خروج پست موجودی فاکتورشده از فروش

صدور فاکتور موجودی تراکنش مالی مستقلی دارد و از قبل برای هر بسته کار ReadyInventoryRefresh ثبت می‌کند. تأیید ادمین، موفقیت صدور و ارسال در صف را اعلام می‌کند؛ حذف/ویرایش تلگرام پس از ثبت فاکتور در callback انجام نمی‌شود، تا خطای پست به‌اشتباه خطای صدور نشان داده نشود.

worker ابتدا حذف همان پیام ثبت‌شده را امتحان می‌کند. حذف موفق یا پاسخ قطعی «پیام وجود ندارد» شناسهٔ پیام را پاک می‌کند. خطای موقت شناسه را برای تلاش بعدی نگه می‌دارد. اگر تلگرام حذف را ممنوع کند، مثلاً پیام بیش از ۴۸ ساعت عمر داشته باشد، همان پیام به «فروخته شد» ویرایش و دکمه‌های خرید کاملاً حذف می‌شوند؛ پیام جایگزین منتشر نمی‌شود.

رسید InventoryPostRetirement به شناسهٔ لیست، گروه/کانال و شمارهٔ دقیق پیام مقید است. فقط پس از ویرایش موفق یا تأیید بدون تغییر، رسید ثبت می‌شود. شناسهٔ واقعی پیام برای سابقه و حذف دستی می‌ماند. نگهداری دوره‌ای برای همان پیامِ خارج‌شده از فروش کار تکراری نمی‌سازد؛ رسید انتشار دیرهنگام با پیام متفاوت همچنان پاک‌سازی مستقل دارد. ویرایش ناموفق به‌عنوان خروج موفق ثبت نمی‌شود و قابل تلاش مجدد است.

حذف کامل پیامی که تلگرام حذفش را برای ربات محدود کرده، به ادمین کانال در برنامهٔ تلگرام نیاز دارد. مبلغ، پرداخت، گیرنده، درخواست و فاکتور به‌علت مشکل نمایش عمومی تغییر نمی‌کنند. رزروهای قبل از صدور و لیست‌های معمولی وارد مسیر حذف موجودی نمی‌شوند. تست‌ها صرفاً روی SQL توسعه و فرستندهٔ جعلی‌اند؛ اصلاح مورد ۱۰۵۲ فقط همان پست را از فروش خارج کرده است.
