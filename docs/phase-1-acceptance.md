# معیار پذیرش فاز یک زیباشه

فاز یک زمانی تکمیل است که مسیر واقعی مشتری از تلگرام و مسیر عملیاتی ادمین روی سرور Production، نه فقط در تست‌های واحد، با شواهد قابل‌تکرار موفق شده باشد.

## وضعیت فعلی

- [x] مدل مشتری مشترک برای username، TelegramId و موبایل
- [x] سفارش، اعتبار، پرداخت، فاکتور، موجودی، دکانت و ارسال
- [x] ربات تلگرام و Outbox قابل retry
- [x] نگاشت گروه اختصاصی مشتری و ورود امن CSV
- [x] فعال‌سازی گروه فقط پس از تأیید عضویت ربات
- [x] مقصد اختصاصی n8n بدون fallback خصوصی
- [x] گزارش شکست ارسال و هشدار ادمین
- [x] Dockerfile، Compose، preflight، smoke test و CI
- [x] قرارداد نسخه‌بندی‌شده n8n
- [ ] استقرار API و SQL Server روی VPS با backup آزمایش‌شده
- [ ] دامنه HTTPS و webhook واقعی تلگرام
- [ ] استقرار n8n و ساخت سه workflow عملیاتی
- [ ] ورود اطلاعات واقعی مشتریان و گروه‌ها به Production
- [ ] تست End-to-End و rollout مرحله‌ای

## Gate 1: کیفیت نسخه

فرمان `deploy/verify-release.sh` باید با خروجی نهایی `GO` تمام شود؛ استفاده از `--skip-containers` برای مدرک نهایی Production قابل قبول نیست.

- Build حالت Release بدون warning موفق است.
- همه تست‌های خودکار موفق‌اند.
- EF Core هیچ تغییر مدل بدون migration ندارد.
- Docker image در CI ساخته می‌شود.
- Secret یا فایل session وارد Git نشده است.

شواهد: لینک اجرای CI و شناسه Commit منتشرشده.

## Gate 2: زیرساخت Production

- `deploy/preflight.sh` موفق است.
- دیتابیس قبل از migration backup دارد.
- بازیابی backup روی دیتابیس جداگانه عملاً آزمایش شده است.
- فقط پورت‌های 22، 80 و 443 عمومی‌اند؛ API روی loopback قرار دارد.
- HTTPS معتبر، health check و log rotation فعال‌اند.
- `deploy/smoke-test.sh https://API_DOMAIN` تمام مراحل را PASS می‌کند.
- گزارش `GET /api/system/readiness` برای پایلوت مقدار `readyForPilot: true` دارد.

## Gate 3: اتصال تلگرام

- webhook با `message`، `callback_query` و `my_chat_member` ثبت شده است.
- درخواست بدون secret معتبر پردازش نمی‌شود.
- مشتری آزمایشی با username متصل می‌شود و در صورت نیاز اتصال موبایل کار می‌کند.
- فرمان‌های `/start`، `/lists`، `/orders`، `/balance`، `/addresses` و `/track` در گفت‌وگوی خصوصی پاسخ درست دارند.
- پیام گروهی مشتری به‌عنوان فرمان خصوصی پردازش نمی‌شود.

## Gate 4: گروه اختصاصی مشتری

- گروه آزمایشی فقط به همان مشتری نگاشت شده است.
- اضافه‌شدن ربات گروه را فعال و حذف‌شدن آن گروه را غیرفعال می‌کند.
- `smoke-test.sh` با UUID گروه، علاوه بر HTTP 202، رسیدن Outbox به وضعیت `Processed` را حداکثر طی ۳۰ ثانیه تأیید می‌کند و پیام تست در همان گروه دیده می‌شود.
- یک ChatId نمی‌تواند به دو مشتری متصل شود.
- اطلاعات مالی و آدرس مشتری داخل گروه منتشر نمی‌شود.

## Gate 5: workflowهای n8n

برای هر سه رویداد `InvoiceIssued`، `OrderDecanted` و `OrderShipped`:

- امضا، timestamp و EventId قبل از side effect اعتبارسنجی می‌شوند.
- اجرای تکراری EventId پیام یا فایل تکراری ایجاد نمی‌کند.
- مقصد دقیقاً `data.Delivery.ChatId` است.
- نبود Delivery باعث توقف امن و ایجاد مورد پیگیری می‌شود.
- فاکتور PDF، عکس دکانت و رسید پستی به گروه آزمایشی می‌رسند.
- callback فایل در ERP ثبت و در جزئیات سفارش قابل مشاهده است.
- شکست دائمی ارسال، گروه را غیرفعال و برای ادمین هشدار ایجاد می‌کند.

## Gate 6: سناریوی End-to-End

یک سفارش آزمایشی با اطلاعات غیرواقعی مراحل زیر را طی می‌کند:

1. مشتری از ربات لیست فروش را می‌بیند و سفارش می‌سازد.
2. موجودی و اعتبار فقط یک بار رزرو می‌شوند.
3. پرداخت ثبت و توسط ادمین تأیید می‌شود.
4. فاکتور صادر و PDF آن به گروه درست ارسال می‌شود.
5. سفارش دکانت می‌شود و عکس اپراتور به همان گروه می‌رسد.
6. آدرس انتخاب، مرسوله ایجاد و رسید پستی ارسال می‌شود.
7. مشتری کد رهگیری و فایل‌های سفارش را در ربات می‌بیند.
8. اجرای دوباره callbackها یا webhookها داده تکراری ایجاد نمی‌کند.

شواهد باید شامل OrderNumber، EventIdها، زمان ارسال، پاسخ callback و تصویر پیام‌های گروه آزمایشی باشد؛ Token، API key، موبایل، آدرس و اطلاعات مالی در شواهد عمومی پوشانده می‌شوند.

## rollout گروه‌ها

گسترش عضویت ربات به ۵۵۶۴ گروه یک عملیات مستقل از توسعه نرم‌افزار است و مرحله‌ای انجام می‌شود:

1. یک گروه داخلی آزمایشی
2. ده گروه با مشتریان هماهنگ‌شده
3. پنجاه گروه
4. دویست‌وپنجاه گروه
5. ادامه در batchهای کنترل‌شده تا پوشش کامل

بعد از هر batch، گزارش `/api/telegram-groups/readiness`، شکست‌های حل‌نشده و نمونه پیام‌های مقصد کنترل می‌شوند. در صورت ارسال به مقصد اشتباه، افشای اطلاعات، افزایش غیرعادی خطا یا هشدار rate limit، rollout فوراً متوقف می‌شود؛ گروه‌های جدید تا بررسی فعال نمی‌شوند.

## تعریف Done

فاز یک Done است اگر همه Gateها موفق باشند، یک backup قابل‌بازیابی وجود داشته باشد، End-to-End واقعی بدون اقدام دستی پنهان اجرا شود و حداقل ۲۴ ساعت پایلوت بدون خطای بحرانی کار کند. پوشش کامل همه گروه‌ها می‌تواند پس از تأیید فاز یک ادامه یابد، اما ارسال عمومی قبل از موفقیت پایلوت مجاز نیست.
